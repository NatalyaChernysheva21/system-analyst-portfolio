## Управление аккаунтом

### Регистрация пользователя

**User Story**

Как пользователь, я хочу зарегистрироваться в приложении, чтобы начать пользоваться умным домом.

**Критерии приемки**

- Пользователь может зарегистрироваться в приложении.
- Для регистрации пользователь указывает email и пароль.
- После успешной регистрации пользователь получает доступ к приложению.
- Пользователь не может зарегистрироваться с уже существующим email.
- Пароль должен соответствовать требованиям безопасности.

### Вход в аккаунт

**User Story**

Как пользователь, я хочу войти в свой аккаунт, чтобы получить доступ к своему дому.

**Критерии приемки**

- Пользователь может войти в аккаунт с помощью email и пароля.
- После успешного входа пользователь получает доступ к своему дому.
- Пользователь не может войти с неверным паролем.
- Пользователь не может войти с несуществующим email.
- При ошибке авторизации отображается сообщение об ошибке.

### Выход из аккаунта

**User Story**

Как пользователь, я хочу выйти из аккаунта, чтобы защитить свои данные при завершении работы с приложением.

**Критерии приемки**

- Пользователь может выйти из учетной записи через интерфейс приложения.
- После успешного выхода пользователь теряет доступ к функционалу умного дома.
- После выхода пользователь перенаправляется на экран авторизации.

### Восстановление пароля

**User Story**

Как пользователь, я хочу восстановить пароль, если я его забыл, чтобы не потерять доступ к системе.

**Критерии приемки**

- Для восстановления пароля пользователь обязан указать email.
- Email должен проходить проверку на корректность формата.
- Если email зарегистрирован в системе, пользователю отправляется письмо для восстановления пароля.
- После успешной отправки письма отображается уведомление об успешной отправке.
- Если email отсутствует в системе, отображается сообщение «Пользователь не найден».
- Если поле email пустое, отображается сообщение «Введите email».
- При некорректном формате email отображается сообщение «Некорректный формат email».
- При наличии ошибок валидации запрос на восстановление пароля не отправляется.

## Управление домом

### Создание дома

**User Story**

Как пользователь, я хочу создать свой дом в приложении, чтобы управлять устройствами в рамках одного пространства.

**Критерии приемки**

- Для создания дома пользователь должен указать название дома.
- Название дома является обязательным полем.
- После успешного создания дом отображается в списке домов пользователя.
- После создания дома пользователю доступен функционал добавления устройств.

### Приглашение пользователей в дом

**User Story**

Как пользователь, я хочу приглашать других пользователей в дом, чтобы они могли управлять устройствами вместе со мной.

**Критерии приемки**

- Только владелец дома может приглашать пользователей.
- Для отправки приглашения пользователь обязан указать email.
- Email должен проходить проверку на корректность формата.
- Приглашение может быть отправлено только зарегистрированному пользователю.
- Пользователь не может пригласить участника, который уже имеет доступ к дому.
- После успешной отправки приглашения отображается уведомление «Приглашение отправлено».
- После принятия приглашения пользователь получает доступ к дому и устройствам.
- Если пользователь не найден, отображается сообщение «Пользователь не найден».
- Если email не заполнен, отображается сообщение «Введите email».
- При некорректном формате email отображается сообщение «Некорректный формат email».
- При наличии ошибок валидации приглашение не отправляется.

### Управление доступами пользователей дома

**User Story**

Как владелец дома, я хочу управлять доступами пользователей дома, чтобы контролировать всех участников дома и их права доступа.

**Критерии приемки**

- Владелец дома может просматривать список всех пользователей, привязанных к дому.
- Владелец дома может назначать роль пользователю.
- Владелец дома может изменять роль существующего пользователя.
- Владелец дома может удалять пользователя из дома.
- После удаления пользователь теряет доступ к дому.
- Только владелец дома может управлять пользователями и их правами доступа.
- При выполнении критических действий (удаление пользователя, смена владельца) требуется подтверждение.

## Управление комнатами

### Создание комнаты

**User Story**

Как пользователь, я хочу создавать комнаты, чтобы структурировать устройства по зонам дома.

**Критерии приемки**

- Пользователь с доступом к дому может создавать комнаты.
- Для создания комнаты пользователь обязан указать название комнаты.
- После успешного создания комната отображается в списке комнат дома.
- После создания комнаты пользователю доступно добавление устройств в комнату.

### Выбор типа комнаты

**User Story**

Как пользователь, я хочу выбирать тип комнаты, чтобы проще ориентироваться в доме.

**Критерии приемки**

- Пользователь может выбрать тип комнаты при создании или редактировании комнаты.
- Тип комнаты выбирается из предопределенного списка.
- Пользователь может изменить тип уже существующей комнаты.
- После сохранения комнаты отображается выбранный тип комнаты.

### Изменение названия комнаты

**User Story**

Как пользователь, я хочу менять название комнаты, если оно мне не подходит.

**Критерии приемки**

- Пользователь может изменить название существующей комнаты.
- Для сохранения нового названия пользователь обязан указать название комнаты.
- После успешного изменения новое название отображается в списке комнат и на экране комнаты.
- Если название комнаты пустое, отображается сообщение «Введите название комнаты».

### Удаление комнаты

**User Story**

Как пользователь, я хочу удалять комнаты, если они больше не нужны.

**Критерии приемки**

- Пользователь может удалить существующую комнату.
- Перед удалением комнаты пользователь должен подтвердить действие.
- После успешного удаления комната исчезает из списка комнат.

### Добавление устройства в комнату

**User Story**

Как пользователь, я хочу добавлять устройство в комнату, чтобы организовать дом.

**Критерии приемки**

- Пользователь может добавить устройство только после авторизации.
- Пользователь может добавить устройство по уникальному номеру или QR-коду.
- Пользователь может добавить устройство в существующую комнату.
- После успешного добавления устройство отображается в выбранной комнате.
- Пользователю становится доступно управление устройством после успешного подключения.
- Система поддерживает только устройства собственного производства.
- Неподдерживаемые устройства не могут быть добавлены.
- Одно устройство не может быть добавлено повторно.
- Если устройство уже зарегистрировано, отображается сообщение «Устройство уже добавлено».
- Если пользователь не указал номер устройства и не отсканировал QR-код, отображается сообщение «Добавьте устройство по номеру или QR-коду».
- При ошибке распознавания QR-кода отображается сообщение «Не удалось распознать QR-код».

### Удаление устройства из комнаты

**User Story**

Как пользователь, я хочу удалять устройство из комнаты, чтобы перемещать его.

**Критерии приемки**

- После удаления устройство перестает отображаться в выбранной комнате.
- Пользователь должен подтвердить удаление устройства из комнаты.
- При отмене действия изменения не применяются.

### Управление всеми устройствами комнаты

**User Story**

Как пользователь, я хочу включать и выключать все устройства в комнате одной кнопкой, чтобы быстро управлять пространством.

**Критерии приемки**

- Пользователь может включать и выключать все устройства в комнате одной кнопкой.
- Команда применяется ко всем устройствам в комнате одновременно.
- Интерфейс корректно отображает общее состояние устройств в комнате.

## Управление устройствами

### Добавление устройства

**User Story**

Как пользователь, я хочу добавлять устройство через QR-код или вручную по ID, если QR-код не работает, чтобы быстро подключать его.

**Критерии приемки**

- Пользователь может добавить устройство по QR-коду или вручную по ID.
- При ошибке сканирования QR-кода пользователю доступен ручной ввод ID.
- После успешного подключения устройство отображается в списке устройств дома.
- Пользователю становится доступно управление устройством после успешного подключения.
- Система поддерживает только устройства собственного производства.
- Неподдерживаемые устройства не могут быть добавлены.
- Одно устройство не может быть добавлено повторно.
- Если устройство уже зарегистрировано, отображается сообщение «Устройство уже добавлено».
- При ошибке распознавания QR-кода отображается сообщение «Не удалось распознать QR-код».
- Если устройство недоступно или подключение невозможно, отображается соответствующее сообщение об ошибке.

### Удаление устройства

**User Story**

Как пользователь, я хочу удалять устройство, если оно сломалось или больше не используется.

**Критерии приемки**

- Пользователь может удалить устройство из дома.
- Перед удалением устройство требует подтверждения пользователя.
- После удаления устройство полностью исчезает из списка устройств дома.
- При отмене удаления устройство остается без изменений.

### Включение и выключение устройства

**User Story**

Как пользователь, я хочу включать и выключать устройство, чтобы управлять его состоянием.

**Критерии приемки**

- Пользователь может включать и выключать устройство после авторизации.
- Состояние устройства синхронизируется и отображается в интерфейсе.
- Устройство должно корректно отражать состояния «Включено» и «Выключено».

### Контроль дублирования устройства

**User Story**

Как пользователь, я хочу, чтобы одно устройство нельзя было добавить дважды, чтобы не путаться где какое устройство подключено.

**Критерии приемки**

- Одно физическое устройство может быть добавлено в систему только один раз.
- При попытке повторного добавления устройство определяется по уникальному ID или QR-коду.
- При повторном добавлении устройство не добавляется заново.
- Пользователь получает сообщение «Устройство уже добавлено».

### Режим энергосбережения

**User Story**

Как пользователь, я хочу включать и выключать режим энергосбережения, чтобы экономить энергию.

**Критерии приемки**

- Пользователь может включать и выключать режим энергосбережения у устройства.
- При включении и отключении режима отображаются соответствующие уведомления.

**Примечание**

При включении режима энергосбережения устройство может отвечать на команды с задержкой.

Тексты уведомлений и ошибок должны быть согласованы с UX-редактором.

## Автоматизация

### Создание сценария автоматизации

**User Story**

Как пользователь, я хочу создавать сценарии автоматизации, чтобы устройства работали автоматически.

**Критерии приемки**

- Пользователь может создавать сценарии автоматизации устройств.
- Сценарий должен содержать название, условие и список устройств.
- Сценарий автоматически запускается при выполнении условия.
- При запуске сценария выполняются заданные действия для устройств.

### Удаление сценария

**User Story**

Как пользователь, я хочу удалять сценарии, если они больше не нужны.

**Критерии приемки**

- Пользователь может удалить сценарий автоматизации.
- Перед удалением требуется подтверждение действия.
- После удаления сценарий полностью исчезает из списка.
- При отмене удаления сценарий остается без изменений.

### Ручной запуск сценария

**User Story**

Как пользователь, я хочу запускать сценарии вручную, чтобы быстро выполнять набор действий.

**Критерии приемки**

- Пользователь может запускать сценарии вручную.
- При запуске выполняются все действия, заданные в сценарии.
- Пользователь получает статус выполнения сценария.

### Запуск сценария по расписанию

**User Story**

Как пользователь, я хочу запускать сценарии по расписанию, чтобы автоматизировать рутину.

**Критерии приемки**

- Пользователь может создавать сценарий с привязкой к расписанию.
- Пользователь может задавать время и дату запуска сценария.
- Пользователь может задавать повторяющееся расписание (ежедневно, еженедельно, по дням недели).
- Пользователь может редактировать расписание существующего сценария.
- Пользователь может отключать и включать расписание сценария.
- Пользователь может удалять расписание сценария.
- Сценарий выполняется автоматически в указанное время.
- При наступлении времени запуска сценарий выполняется без участия пользователя.
- Пользователь получает уведомление о выполнении сценария.
- Если выполнение сценария невозможно, пользователь получает уведомление об ошибке.
